# Forge: telemetry recorder, slabs, MCP and the chat agent

Date: 2026-10-01 08:56 UTC – 2026-10-02 22:27 UTC. Reference documentation: `workspaces/forge/README.md` and the `forge-dev` skill. Voice is in `2026-10-02-voice-agent.md`.

## Context and goal

Record everything the robot publishes into ClickHouse on one clock and let agents answer questions about it: a small standalone version of the "curated queries + validated ad-hoc SQL" idea (slabs with grain and measure metadata, a fast path that runs a reviewed query, a heavy path where a sub-agent writes SQL that must pass validation), plus anomaly detection with time-series foundation models. Name chosen by the owner; curated queries were first called "recipes", then **slabs**.

## Architecture (as of 2026-10-03)

- **Writer** subscribes once per subject, validates with zod (`src/streams.ts`), writes one INSERT per table every 10 s with an `insert_deduplication_token`, bisects rejected batches, sends bad rows to `dead_letters/`. Logs come from the JetStream `LOGS` stream through a durable consumer, acked after the insert.
- **Runs.** Every row has a `run_id`; manual runs via `pnpm forge run start/stop`, otherwise an `auto` run that the writer opens on start and closes after 60 s without messages. A writer restart starts a new run, so "the latest run" can miss events around a deploy.
- **ClickHouse users.** `forge_writer` owns the database; `forge_reader` is read-only with limits (30 s, 300 MB, 16 concurrent queries — 4 was too few and broke `robot_status` during a chat).
- **SQL gate.** Static checks (one statement, function allowlist, no table functions, no `system.*`, no `FORMAT`/`INTO OUTFILE`, joins on `run_id` plus a time key) and then ClickHouse `EXPLAIN`. A review found `SELECT * APPLY(fn)` bypassed the allowlist; fixed in `5f09181`.
- **Agent.** Tools for slabs (BM25 search over slab metadata), validated queries, the metric graph, `investigate` (walks the graph upstream and ranks causal chains), `detect_anomalies`, logs, robot status, missions with approval, `go_to`/`find_object`/places, `reset_map` (approval). Approvals are signed, single-use, 60 s TTL; the server re-checks pose freshness and a clear path before publishing a mission.
- **Anomaly detection.** Signals are resampled in ClickHouse (10 Hz for windows ≤ 15 min, else 1 Hz) and forecast jointly by `amazon/chronos-2` on tsfm.ai with up to 4 covariates picked from graph edges; `NX-AI/TiRex-2` is the fallback. Thresholds at the 99.8th percentile of each signal's clean windows, plus a run-wide baseline at matching covariate levels (catches slow events such as 15 s of pushing against a wall). On 9 hand-labelled events: recall 9/9, precision 0.55–0.6.

## Incidents

- **Colima at 340 % CPU** on the laptop: ClickHouse with system logs on and many small inserts. System logs off, one insert per table per second: 20–40 % of a core.
- **Poisoned batch:** one message with a garbage timestamp made ClickHouse reject a batch that the writer retried forever; about 8 min of IMU rows lost. The writer now validates timestamps and retries only connection errors.
- **Live field rename** (`battery_voltage` → `supply_voltage`) dropped about 2 min of RoboClaw rows.
- **Chat approval never worked** until 2026-10-01 23:20: a language reminder was appended after the tool-approval response, and the AI SDK only executes an approved tool when the last message is that response ("No tool output found for function call").
- **Same-origin GETs carry no `Origin`**, so the token endpoint refused the HUD once nginx served both (403).
- **`docker compose restart` does not pick up a rebuilt image**: the writer ran old code and did not record `rabbit.map.reset`. Deploys now force-recreate.
- **On the robot ClickHouse used ~75 % of a core** with 1 s flushes (8699 inserts in 10 min); with 10 s flushes 96 inserts/min and 28.9 % of a core.
- **Anomaly false positives on a charging battery**: the run baseline's spread was tiny, so 0.01 V counted as 6σ. A minimum absolute threshold was proposed, not implemented.
- **Eval drift.** After moving to a fresh database on the robot, `pnpm forge eval` passed 14/25: the cases expect runs that only existed in the old laptop database.
- **Known data bug:** in `pose`, `pitch_deg` holds yaw (Euler axes mapped wrongly in `src/streams.ts`); fixed on 2026-10-03 for new rows, see `2026-10-03-forge-parquet-chdb.md`.

## Sizes

ClickHouse on the robot grows about 15 MiB per hour of driving; on 2026-10-02 the largest tables were `imu` 59.6 MiB / 3.78 M rows, `power` 33.8 MiB, `roboclaw` 20.0 MiB, `obstacle` 18.4 MiB, `pose` 15.5 MiB. Memory is capped at 768 MiB inside ClickHouse and 900 MB by cgroup; it sits at the limit (thousands of reclaim events) without affecting the control path.
